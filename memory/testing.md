# Testing and verification

The repo currently has no lint or automated test scripts. Verification is
build-based plus manual/UI smoke checks.

## Build

- Builds run only inside Docker: `docker compose build`, or
  `docker compose up --build -d` to build and start the app.
- Never run frontend or backend build/dev scripts directly on the host machine.
- Frontend styles are authored in SCSS. The only CSS files are generated by Vite
  in `frontend/dist`; `git ls-files '*.css'` must return nothing.
- Run `git diff --check` before committing.

## Docker smoke test

- `docker compose up --build -d`.
- `docker compose ps` — `api` is healthy and `web` is published on `WEB_PORT`.
- `curl -fsS -o /dev/null -w '%{http_code}' http://localhost:$WEB_PORT/` -> `200`.
- `curl -fsS -o /dev/null -w '%{http_code}' http://localhost:$WEB_PORT/api/health` -> `200`.

`WEB_PORT` comes from `.env`; it is deployment-specific and must never be
hardcoded in docs, config, or code.

## UI checks

Use headless Playwright/Chrome and check at least mobile (390px), tablet (768px),
and desktop (1200px) widths.

- Layout: content column max 576px and centered; side background `#f5ead8`; the
  tabbar spans the full viewport with its buttons in a centered 576px container;
  no horizontal scroll (`document.documentElement.scrollWidth === innerWidth`).
- Tabbar: icons stay outline + muted on both active and inactive tabs.
- Title: `document.title` equals the pet name once loaded, and `Питомец` while
  locked or before the name is known.
- Weight: the create sheet is unchanged; tapping a row opens a prefilled edit
  sheet; the red delete button sits below Save; the header shows `Изменение`;
  the oldest row shows a gray `0 кг` badge; a date collision shows the 409
  message.
- Pet: the age banner title is `Возраст`, and the age value uses a single
  `16px`/`600` style.
- Auth: obtain a token with `POST /api/auth/login` using `APP_PASSWORD`; never
  print the password or token to logs. Remove temporary token files afterwards.
  For Playwright, a token can be written to a temporary file inside the `web`
  container (for example `/usr/share/nginx/html/.verify-token`), read from the
  browser to set `localStorage.auth_token`, and then deleted with
  `docker compose exec -T web rm -f /usr/share/nginx/html/.verify-token`.

## Visual regression (style refactors)

Before changing shared styles, capture a baseline with Playwright from the
current build, then repeat the same capture after the change under identical
conditions.

- Cover 390/768/1200 px and every screen/state: lock, lock error, home, month
  (current/previous/next), weight, pet, weight create/edit/error/focus states,
  walkers sheet, color palette, rename mode, hover states, and the offline bar.
- Save full-page and key-element screenshots outside the repo (for example under
  `/tmp/`).
- Keep the browser, viewport, device scale factor, database state, timezone, and
  auth token identical between runs.
- Before each run unregister the service worker and delete Cache Storage;
  otherwise `autoUpdate` may keep serving the old CSS. Wait for network idle and
  `document.fonts.ready`, reset hover/scroll, hide the caret, and disable
  animations.
- Compare screenshots pixel-by-pixel: the result must be 0 differing pixels.
  Also compare bounding boxes and computed styles for every visible element; any
  difference is a regression. Do not use tolerances.
- Delete temporary screenshots, token files, and baseline data afterwards.

## Test data

- Use temporary weight entries on dates not used by real data, then delete them
  after the check.
- Confirm cleanup with `GET /api/weights`.
- Never put real names, photos, or passwords into test fixtures, commits, or docs.
